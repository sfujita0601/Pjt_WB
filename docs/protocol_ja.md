# 研究室向け 標準解析手順（Western blot フィルム画像）

対象：研究室で Western blot を定量する学生・教員
関連：`docs/theory_ja.md`（式と前提）、`docs/validation_imagej.md`（Fiji/ImageJ との照合）、`docs/user_guide_ja.md`（画面操作の詳細）

この手順書は、**フィルムの露光 → スキャン → アプリでの解析 → 記録と報告**を研究室内でそろえるためのものです。迷ったときは、ここに書いた保守的な初期値を使い、変えた場合はその理由を記録してください。

> 本アプリの数値は、較正されていない**相対的な画像強度**です。光学密度やタンパク質の量ではありません。スキャン条件がそろっていないと、同じ解析手順でも比較できません。

---

## 1. フィルムの露光

1. **露光時間を変えて複数枚**撮ります（例：短・中・長の 3 段階以上）。強いバンドと弱いバンドの両方が、飽和せず、かつ背景から見分けられる露光を後で選ぶためです。
2. 目的バンドが**真っ黒につぶれていない**（飽和していない）露光を、定量用に 1 枚選びます。迷ったら短いほうを選びます。
3. Loading control（actin、GAPDH など）は量が多く飽和しやすいので、Target とは**別に露光を選ぶ**ことがあります。その場合も、選んだ露光をそれぞれ記録します。
4. 同じ膜の別露光は**独立な反復ではありません**。定量に使うのは 1 枚だけです。
5. 線形範囲（信号がタンパク質量に比例する範囲）は、可能なら**希釈系列**（例：同じ試料を 1/4、1/2、1 倍でロード）で確かめます。本アプリには希釈系列による線形範囲の QC 機能はまだありません（Phase 2 以降）。確認した場合は、その結果を記録に添付します。

## 2. スキャン設定（推奨）

| 項目 | 推奨設定 | 理由 |
|---|---|---|
| スキャンモード | **透過モード**（透過原稿ユニット／フィルムモード） | フィルムは光を透過させて濃度を測るもの。反射モードでは、紙の上の黒さとして読むことになり、濃度との関係がさらに不確かになる |
| 色 | **グレースケール** | カラーで取り込むと、グレースケールへの変換式の違いで値が変わる（本アプリは BT.601 の重みで変換し、注意を表示する） |
| bit depth | **16-bit**（48-bit カラーではなく 16-bit グレー） | 階調が細かく、濃いバンドと薄いバンドの差を保ちやすい。8-bit しか選べない場合はそのことを記録する |
| 自動補正 | **すべてオフ**（自動露出、自動レベル、自動コントラスト、ガンマ補正の変更、シャープネス、ゴミ除去、逆光補正など） | 自動補正は画像ごとに違う非線形変換をかけるので、画像間で比較できなくなる。いったん補正された値は解析では元に戻せない |
| 解像度 | **300 dpi 以上（研究室標準として 600 dpi を推奨）**。研究室内で固定する | バンドの幅に十分な画素数を確保するため。解像度を変えると ROI の画素数が変わり、積分値も変わる |
| 範囲 | フィルム全体（ラベルやマーカーを含む）。プレビューで切り抜く場合も余白を残す | 後から位置関係を確認でき、背景を取る余地が残る |
| ファイル形式 | **非圧縮 TIFF**（または LZW などの可逆圧縮 TIFF）。PNG も可 | JPEG は不可逆圧縮で画素値が変わる（本アプリは警告を出す） |
| 向き | 回転・反転をスキャナー側でしない。ずれた場合も原画像は保存し、別名で処理する | 原画像を保持するため |
| 同じ実験の画像 | **同じスキャナー・同じ設定**で取り込む | 設定が違う画像どうしは値を比較できない |

注意：

- スキャナーの応答（画素値と濃度の関係）は機種や設定で違い、線形とは限りません。濃度既知のステップタブレットで較正する方法がありますが、本アプリには較正機能はありません（Phase 2 以降の検討事項）。
- 原画像ファイルは**解析前に読み取り専用の場所へ保存**し、上書きしません。本アプリは原画像の SHA-256 ハッシュを記録し、ファイルを変更しません。
- 画像の明るさ・コントラストを画像編集ソフトで調整して保存し直したファイルは、定量に使いません。

### 2.1 ファイル命名

次の要素を、決まった順に `_` でつなぎます。日本語・空白・記号（`/ \ : * ? " < > |`）は使いません。

```
日付_実験ID_膜ID_抗体(タンパク質)_露光_解像度.tif
例：20261025_EXP012_M01_pERK_exp030s_600dpi.tif
    20261025_EXP012_M01_actin_exp005s_600dpi.tif
```

- 同じ膜を再プローブした場合は膜 ID を変えず、抗体名で区別します（例：`M01_pERK` → `M01_tERK`）。
- 再スキャンした場合は末尾に `_scan2` などを付け、古いファイルを消しません。

### 2.2 スキャン時に記録するメタデータ

実験ノート（または画像と同じフォルダの記録ファイル）に、次を書きます。

| 区分 | 記録する項目 |
|---|---|
| 試料 | 実験 ID、試料 ID とレーンの対応、群、biological replicate ID、technical replicate ID、ロード量 |
| 膜・抗体 | 膜 ID、転写条件、一次・二次抗体（メーカー、カタログ番号、希釈）、検出試薬、再プローブ／ストリップの有無と順番 |
| フィルム | フィルムの種類、露光時間、現像条件（自動現像機・手現像） |
| スキャン | スキャナー機種、ソフトウェア名とバージョン、透過／反射、グレースケール／カラー、bit depth、解像度、自動補正をすべてオフにしたこと、スキャン日 |
| ファイル | ファイル名、保存場所 |

本アプリでは、画像ごとに `experiment_id`、`blot_id`、`membrane_id`、`exposure_id`、タンパク質名を入力し、試料表に `sample_id`、`group`、`bio_rep`、`tech_rep` を入力します。試料表は CSV で一括取込できます（例：`examples/synthetic_samples.csv`）。

## 3. アプリでの解析手順（概略）

画面の各ページ（左サイドバー）を上から順に進めます。ボタン名などの細かい操作は `docs/user_guide_ja.md` を参照してください。

1. **プロジェクト**：新規プロジェクトを作成し、保存場所を決めます。途中でもこまめに保存します。
2. **画像・試料情報**
   - 画像を登録します（TIFF/PNG 推奨）。bit depth、画像サイズ、SHA-256 が記録されます。読込時の警告（JPEG、カラー変換、16-bit なのに最大値が 4095 以下など）を確認します。
   - 画像ごとにタンパク質名・膜 ID・露光 ID などを入力し、**極性**を確認します（フィルムのスキャン像は通常「暗いバンド」）。
   - 同じ膜の別露光は、定量に使う 1 枚だけを「定量に使う」にします。
   - 試料表（sample_id、群、biological replicate、technical replicate）を入力または CSV で取り込みます。
3. **レーン・バンド ROI**
   - レーン候補を提示させ、**必ず目で確認して**位置と幅を直します（候補は自動検出の結果ではなく目安です）。
   - 各レーンに sample_id を割り当てます。Target と Loading control が別の画像でも、**同じ sample_id** を割り当てることで対応付けられます。
   - バンドごとに矩形 ROI を置き、**同じタンパク質の ROI の大きさをそろえます**。
4. **背景補正・定量**
   - 背景法を選びます。初期値は「同一レーンのバンド近傍（上下）」（gap = 3 px、height = 5 px）です。
   - 背景帯がほかのバンドや smear に重ならないか、プロファイル表示と画像で確認します。
   - raw_sum、背景値 b、S、画素数 N を確認します。負の S は丸めずに残ります。
5. **QC**
   - 警告（飽和・黒つぶれ候補、ROI の大きさの不一致、重複、背景との交差、sample_id の重複・未割当、露光の重複など）を一つずつ確認し、「採用／除外／再撮影推奨」と**理由**を記録します。
   - 学生向けチェックリストを確認します。QC は「疑い」を示すだけで、問題がないことを証明するものではありません。
   - **結果を見てから都合のよいバンドだけを除外しない**でください。除外基準は事前に決めておきます。
6. **正規化**
   - 分子（例：pERK）と分母（例：actin、または total ERK）を明示的に選び、Control 群を選びます。
   - 画面に表示される計算の段階（① 試料ごとの比 → ② technical replicate の平均 → ③ fold to control）と、計算できなかった試料の理由（status）を確認します。
7. **統計**
   - 検定前に、群・biological replicate・画像・膜の割当て一覧を確認します。
   - 2 群の独立比較は Welch の t 検定、同じ bio_rep で対応がある設計は対応のある t 検定を選びます。p 値だけでなく、効果量、95% 信頼区間、n、欠損数、前提の注意を確認します。
   - 3 群以上の ANOVA・多重比較・混合効果モデルは **Phase 2 以降で、未実装**です。必要な場合は、出力した CSV を使って別の統計ソフトで解析し、その方法を記録します。
8. **Figure と出力**
   - 個々の biological replicate を点で示すグラフを作り、PNG/SVG/PDF で保存します。
   - 測定 CSV（`measurements.csv`）、ROI 一覧（`roi_list.csv`）、設定（`settings.json`）、試料表（`samples.csv`）、正規化結果（`normalized_by_sample.csv`、`normalized_by_biorep.csv`）、履歴（`history.csv`）、ROI を重ねた画像（`overlay_<image_id>.png`）を書き出し、原画像と一緒に保管します。
   - Figure 用のバンド画像トリミングや、複数パネルの組み合わせは **Phase 2 以降で、未実装**です。

### 3.1 保守的な初期値とその理由

| 設定 | 初期値 | 理由 |
|---|---|---|
| 極性 | 暗いバンド（`dark`） | フィルムのスキャン像ではバンドが背景より暗いのが普通。反転済み画像や蛍光画像のときだけ `bright` に変える |
| 測定方法 | 矩形 ROI の背景補正積分 S | 定義が単純で、ImageJ の Measure（RawIntDen）と照合できる。プロファイル面積は参考値 |
| 背景法 | 同一レーンのバンド近傍（上下）、gap = 3 px、height = 5 px | バンドと同じ列の背景を使うので、レーンごとの背景の違いと、上下方向の緩やかな傾斜を打ち消しやすい。gap を空けるのはバンドの裾を背景に入れないため。バンドが密集していて背景帯が隣のバンドに重なる場合は、gap・height を変えるか手動背景 ROI を使い、理由を記録する |
| 負の S | 0 に丸めない | 丸めると平均が上に偏り、検出限界以下という情報が失われる |
| ROI の大きさ | 同じタンパク質・同じ画像内でそろえる | 背景推定の誤差は ROI の画素数 N 倍で S に入るため（`docs/theory_ja.md` 3.4 節） |
| technical replicate | 平均してから biological replicate として扱う | technical replicate を独立な n に数えると、n を水増しして p 値が小さくなりすぎる |
| fold の基準 | Control 群の biological replicate 値の平均 | 計算の段階を明確にし、Control 群の平均がちょうど 1 になるようにする |
| 統計 | Welch の t 検定（等分散を仮定しない） | 小さな n で等分散を確かめるのは難しく、等分散を仮定しないほうが安全側 |
| 比の対数変換 | しない | 変換するかどうかはデータを見る前に決めるべきで、ツールが自動で選ぶべきではない |
| OD 変換 | しない | 透過モード・較正なしでは OD を正しく計算できない（`docs/theory_ja.md` 8 節） |
| 膜間の比較 | 行わない（警告のみ） | 膜・露光が違う生の値は直接比べられない。共通参照レーンによる膜間正規化は Phase 2 以降 |

## 4. 結果の記録と報告

### 4.1 保管するもの

- 原画像（スキャンしたままの TIFF）と、その SHA-256。
- プロジェクトファイル（ROI 座標、背景法、設定、QC 判断、履歴を含む）。
- 出力一式（測定 CSV、ROI 一覧、設定 JSON、正規化結果、ROI オーバーレイ画像、Figure）。
- 使わなかった露光の画像も消さずに残します。

### 4.2 報告（論文・発表・ノート）に書く項目

1. **画像取得**：フィルムの種類、露光時間（定量に使った露光）、スキャナー機種、透過/反射、グレースケール、bit depth、解像度、自動補正をオフにしたこと。
2. **定量方法**：使用ソフトウェアとバージョン、矩形 ROI による背景補正積分であること、式 `S = s · (Σp − N·b)`、ROI の大きさ（画素数）、背景法とパラメータ（例：バンドと同じ幅の上下 5 px の帯、間隔 3 px）。
3. **値の性質**：較正されていない相対的な画像強度であること（OD やタンパク質量ではない）。
4. **線形範囲**：希釈系列などで線形範囲を確認したかどうか。未確認ならその旨。
5. **正規化**：分子と分母（例：pERK / actin、pERK / total ERK）、分子と分母が同じ膜か別の膜か、fold to control の基準（Control 群の平均）、計算の段階。
6. **反復と統計**：biological replicate の数（各群の n）とその定義、technical replicate の扱い（平均してから解析）、使った検定（Welch の t 検定／対応のある t 検定）、効果量（Hedges の g／d_z）、95% 信頼区間、p 値、対数変換の有無。
7. **除外**：除外したバンド・試料と、その理由（事前に決めた基準）。
8. **QC**：飽和の疑いなどの警告にどう対応したか。
9. **画像の提示**：Figure のブロット画像に加えた処理（トリミング、明るさ・コントラストの調整は画像全体に一様にかけたか）、別の膜や別の露光を並べた場合はその境界を明示したこと。原画像を提出できるよう保管していること。

### 4.3 書いてはいけない表現の例

- 「タンパク質量が 2.1 倍に増加した」（較正と線形範囲の確認がない場合）→「相対強度（fold to control）が 2.1 倍」
- 「OD を測定した」（OD に変換していない場合）
- 「n = 6」（3 個体 × technical replicate 2 回の場合）→ n = 3
- 「飽和していないことを確認した」（画素値の端値チェックだけの場合）→「画素値の端値（飽和の疑い）がないことを確認した」
