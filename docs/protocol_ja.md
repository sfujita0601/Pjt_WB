# 研究室向け 標準解析手順の推奨案（Western blot フィルム画像）

対象：研究室で Western blot を定量する学生・教員
関連：`docs/theory_ja.md`（式と前提）、`docs/validation_imagej.md`（Fiji/ImageJ との照合）、`docs/user_guide_ja.md`（画面操作の詳細）

この手順書は、**フィルムの露光 → スキャン → アプリでの解析 → 記録と報告**を研究室内でそろえるための**推奨手順**です。迷ったときは、ここに書いた保守的な初期値を使い、変えた場合はその理由を記録してください。

> **この手順書の位置づけ**：スキャナーの機種・設定、ローディングコントロールの取得方法（同じ膜の再プローブ／膜の切り分け／別の膜）、画像サイズ、対応のある設計の頻度など、研究室で**実際に使われている条件はまだ確認していません（未確認）**。以下の設定値は一般的な**推奨**であり、研究室の実際の設定を示すものではありません。実際の条件が決まったら、その条件を記録し、この手順書との違いを明記してください。

> 本アプリの数値は、較正されていない**相対的な画像強度**です。光学密度やタンパク質の量ではありません。スキャン条件がそろっていないと、同じ解析手順でも比較できません。

---

## 1. フィルムの露光

1. **露光時間を変えて複数枚**撮ります（例：短・中・長の 3 段階以上）。強いバンドと弱いバンドの両方が、飽和せず、かつ背景から見分けられる露光を後で選ぶためです。
2. 目的バンドが**真っ黒につぶれていない**（飽和していない）露光を、定量用に 1 枚選びます。迷ったら短いほうを選びます。
3. ローディングコントロール（loading control、actin・GAPDH など）は量が多く飽和しやすいので、Target とは**別に露光を選ぶ**ことがあります。その場合も、選んだ露光をそれぞれ記録します。
   - ローディングコントロールをどう検出するか（同じ膜をストリップして再プローブ、分子量で膜を切り分けて別々に検出、同じ試料を別の膜に流す、など）は実験によって違います。本手順書はどれか一つを前提にしません。**どの方法で取得したかを必ず記録**してください。本アプリは、分子と分母が別の膜（membrane_id が違う）だと「対応付けはできるが、正規化として適切とは限らない」と警告します。
4. 同じ膜の別露光は**独立な反復ではありません**。定量に使うのは 1 枚だけです。
5. 線形範囲（信号がタンパク質量に比例する範囲）は、可能なら**希釈系列**（例：同じ試料を 1/4、1/2、1 倍でロード）で確かめます。本アプリには希釈系列による線形範囲の QC 機能はありません（未実装）。確認した場合は、その結果を記録に添付します。

## 2. スキャン設定（推奨）

下の表は**推奨設定**です。研究室で実際に使っているスキャナーと設定は未確認です。実際に取り込んだ条件は、推奨と違っていても**そのまま記録**してください（2.2 節）。


| 項目 | 推奨設定 | 理由 |
|---|---|---|
| スキャンモード | **透過モード**（透過原稿ユニット／フィルムモード） | フィルムは光を透過させて濃度を測るもの。反射モードでは、紙の上の黒さとして読むことになり、濃度との関係がさらに不確かになる |
| 色 | **グレースケール** | カラーで取り込むと、グレースケールへの変換式の違いで値が変わる（本アプリは BT.601 の重みで変換し、注意を表示する） |
| bit depth | **16-bit**（48-bit カラーではなく 16-bit グレー） | 階調が細かく、濃いバンドと薄いバンドの差を保ちやすい。8-bit しか選べない場合はそのことを記録する。**同じ実験で比べる画像は 8-bit と 16-bit を混ぜない**（本アプリは、同じタンパク質の値に 8-bit と 16-bit が混在すると統計と Figure を止める） |
| 自動補正 | **すべてオフ**（自動露出、自動レベル、自動コントラスト、ガンマ補正の変更、シャープネス、ゴミ除去、逆光補正など） | 自動補正は画像ごとに違う非線形変換をかけるので、画像間で比較できなくなる。いったん補正された値は解析では元に戻せない |
| 解像度 | **300 dpi 以上**（例：600 dpi）。少なくとも同じ実験の中では固定する | バンドの幅に十分な画素数を確保するため。解像度を変えると測定領域（ROI）の画素数が変わり、積分値も変わる。近傍背景の帯の px も解像度に合わせて決める必要がある（3 章の 4） |
| 範囲 | フィルム全体（ラベルやマーカーを含む）。プレビューで切り抜く場合も余白を残す | 後から位置関係を確認でき、背景を取る余地が残る |
| ファイル形式 | **非圧縮 TIFF**（または LZW などの可逆圧縮 TIFF）。PNG も可 | JPEG は不可逆圧縮で画素値が変わる（本アプリは警告を出す） |
| 向き | 回転・反転をスキャナー側でしない。ずれた場合も原画像は保存し、別名で処理する | 原画像を保持するため |
| 同じ実験の画像 | **同じスキャナー・同じ設定**で取り込む | 設定が違う画像どうしは値を比較できない |

注意：

- スキャナーの応答（画素値と濃度の関係）は機種や設定で違い、線形とは限りません。濃度既知のステップタブレットで較正する方法がありますが、本アプリには較正機能はありません（未実装）。
- 原画像ファイルは**解析前に読み取り専用の場所へ保存**し、上書きしません。本アプリは原画像の SHA-256 ハッシュを記録し、ファイルを変更しません。
- 画像の明るさ・コントラストを画像編集ソフトで調整して保存し直したファイルは、定量に使いません。

### 2.1 ファイル命名

次の要素を、決まった順に `_` でつなぎます。日本語・空白・記号（`/ \ : * ? " < > |`）は使いません。

```
日付_実験ID_膜ID_抗体(タンパク質)_露光_解像度.tif
例：20261025_EXP012_M01_pERK_exp030s_600dpi.tif
    20261025_EXP012_M01_actin_exp005s_600dpi.tif
```

- 同じ膜を再プローブした場合は膜 ID を変えず、抗体名で区別します（例：`M01_pERK` → `M01_tERK`）。
- 再スキャンした場合は末尾に `_scan2` などを付け、古いファイルを消しません。

### 2.2 スキャン時に記録するメタデータ

実験ノート（または画像と同じフォルダの記録ファイル）に、次を書きます。

| 区分 | 記録する項目 |
|---|---|
| 試料 | 実験 ID、試料 ID とレーンの対応、群、生物学的反復（biological replicate）の ID、技術的反復（technical replicate）の ID、同じ個体・試料を複数条件で測った場合はその実験単位 ID、実験日・ブロットのまとまり、ロード量 |
| 膜・抗体 | 膜 ID、転写条件、一次・二次抗体（メーカー、カタログ番号、希釈）、検出試薬、ローディングコントロールの取得方法（再プローブ／ストリップ／膜の切り分け／別の膜）とその順番 |
| フィルム | フィルムの種類、露光時間、現像条件（自動現像機・手現像） |
| スキャン | スキャナー機種、ソフトウェア名とバージョン、透過／反射、グレースケール／カラー、bit depth、解像度、自動補正をすべてオフにしたこと、スキャン日 |
| ファイル | ファイル名、保存場所 |

本アプリでは、画像ごとに `experiment_id`、`blot_id`、`membrane_id`、`exposure_id`、タンパク質名を入力し、試料表に `sample_id`、`group`、`bio_rep`、`tech_rep`、必要に応じて `subject_id`（同じ個体・試料を複数条件で測ったときだけ共通にする ID）と `batch_id`（実験日・ブロットなどのまとまり、記録用）を入力します。試料表は CSV で一括取込できます（例：`examples/synthetic_samples.csv`）。

## 3. アプリでの解析手順（概略）

画面の各ページ（左サイドバー）を上から順に進めます。ボタン名などの細かい操作は `docs/user_guide_ja.md` を参照してください。

1. **プロジェクト**：新規プロジェクトを作成し、保存場所を決めます。途中でもこまめに保存します。
2. **画像・試料情報**
   - 画像を登録します（TIFF/PNG 推奨）。bit depth、画像サイズ、SHA-256 が記録されます。読込時の警告（JPEG、カラー変換、16-bit なのに最大値が 4095 以下など）を確認します。
   - 画像ごとにタンパク質名・膜 ID・露光 ID などを入力し、**極性**を確認します（フィルムのスキャン像は通常「暗いバンド」）。
   - 同じ膜の別露光は、定量に使う 1 枚だけを「定量に使う」にします。
   - 試料表（sample_id、群、生物学的反復、技術的反復、必要なら subject_id・batch_id）を入力または CSV で取り込みます。対応のある設計（同じ個体の処理前後など）では、両条件で同じ subject_id にします。同じ日・同じブロットというだけでは同じ subject_id にしません。
   - 比べる画像の bit 深度がそろっているか確認します（8-bit と 16-bit を混ぜない）。
3. **レーン・バンド ROI**
   - レーン候補を提示させ、**必ず目で確認して**位置と幅を直します（候補は自動検出の結果ではなく目安です）。
   - 各レーンに sample_id を割り当てます。Target とローディングコントロールが別の画像でも、**同じ sample_id** を割り当てることで対応付けられます。1 枚の画像に複数のタンパク質がある場合は、バンドごとにタンパク質名を設定し、「表示するタンパク質」で絞り込んで確認します。
   - バンドごとに矩形 ROI を置き、**同じタンパク質の ROI の大きさをそろえます**。
4. **背景補正（background subtraction）・定量**
   - 背景法を選びます。初期値は「同一レーンのバンド近傍（上下）」です。
   - 近傍背景の間隔（gap）と高さ（height）は px で保存されますが、**px の値は解像度とバンドの大きさに依存し、固定の標準値ではありません**（新しい画像の初期値 3 px・5 px も目安にすぎません）。バンド ROI の高さ h に対する**相対的な大きさ**で考え、画面の「h に対する比」（初期値は間隔 30%・高さ 50%、これも目安）から設定できます。同じ実験の画像は同じ考え方で設定し、使った値（px と比率）を記録します。
   - 背景帯がほかのバンドや smear に重ならないか、プロファイル表示と画像で確認します。
   - raw_sum、背景値 b、S、画素数 N を確認します。負の S は丸めずに残ります。
5. **QC**
   - 警告（飽和・黒つぶれ候補、ROI の大きさの不一致、重複、背景との交差、sample_id の重複・未割当、露光の重複など）を一つずつ確認し、「採用／除外／再撮影推奨」と**理由**を記録します。
   - 学生向けチェックリストを確認します。QC は「疑い」を示すだけで、問題がないことを証明するものではありません。
   - **結果を見てから都合のよいバンドだけを除外しない**でください。除外基準は事前に決めておきます。
6. **正規化**
   - 分子（例：pERK）と分母（例：actin、または total ERK）を明示的に選び、対照群（control）を選びます。
   - 画面に表示される計算の段階（① 試料ごとの比 → ② 技術的反復の平均 → ③ 対照群を1とした相対値（fold change）→ ④ log2）と、計算できなかった試料の理由（status）、分子・分母の画像・膜・露光・bit 深度を確認します。
   - タンパク質の役割（Target／ローディングコントロール／phospho／total）を設定し、対応表で各試料に分子・分母のバンドがそろっているか確認します。
7. **統計**
   - 検定前に、群・生物学的反復・subject_id・画像・膜の割当て一覧を確認します。
   - 比べたいもの（2 群／対照群との比較／全群間）、独立か対応ありか、分散の仮定、検定に使う値（線形の比か log2）を、**データを見る前に**決めます。
   - 2 群の独立比較は Welch の t 検定、同じ subject_id で対応がある 2 群は対応のある t 検定です。3 群以上の独立群は、Welch ANOVA ＋ Games–Howell（既定）、または等分散を仮定する場合は一元配置 ANOVA ＋ Dunnett／Tukey です。多重比較の p 値は調整済みです。
   - 対応のある 3 群以上（反復測定）、二要因の設計、混合効果モデルは**未実装**で、本アプリでは検定しません。必要な場合は、出力した CSV を使って別の統計ソフトで解析し、その方法を記録します。
   - p 値だけでなく、効果量、95% 信頼区間、n、欠損数、前提の注意を確認し、結果を `stats_results.csv` に保存します。
8. **Figure と出力**
   - 個々の生物学的反復を点で示すグラフを作り、エラーバー（SD を推奨。SEM・95%CI も選べる）の種類を決めて、PNG/SVG/PDF で保存します。自動生成される図の説明文（エラーバーの種類・n・検定法）を確認して使います。
   - 測定 CSV（`measurements.csv`）、ROI 一覧（`roi_list.csv`）、設定（`settings.json`）、試料表（`samples.csv`）、正規化結果（`normalized_by_sample.csv`、`normalized_by_biorep.csv`）、履歴（`history.csv`）、ROI を重ねた画像（`overlay_<image_id>.png`）、統計結果（`stats_results.csv`）、図（`figure.png/.svg/.pdf`）、図の説明文（`figure_caption.txt`）を書き出し、原画像と一緒に保管します。
   - バンド画像を添える場合は、［Figure］の「バンド画像＋グラフ（複合）」を使います。元画像の連続した領域を切り出し（並べ替え・継ぎ合わせなし）、画像ごとに別の段にし、線形表示だけを使います。保存すると、切り出し座標・表示レベル・元画像のハッシュの記録（`*_bands.json`）と、切り出した原画素（`*_crop_*.tif`）も保存されます。

### 3.1 保守的な初期値とその理由

| 設定 | 初期値 | 理由 |
|---|---|---|
| 極性 | 暗いバンド（`dark`） | フィルムのスキャン像ではバンドが背景より暗いのが普通。反転済み画像や蛍光画像のときだけ `bright` に変える |
| 測定方法 | 矩形 ROI の背景補正積分 S | 定義が単純で、ImageJ の Measure（RawIntDen）と照合できる。プロファイル面積は参考値 |
| 背景法 | 同一レーンのバンド近傍（上下）。gap・height は解像度とバンドの大きさに合わせて決める（目安：バンド ROI の高さ h の 30%・50%。新しい画像の初期値 3 px・5 px は固定の標準値ではない） | バンドと同じ列の背景を使うので、レーンごとの背景の違いと、上下方向の緩やかな傾斜を打ち消しやすい。gap を空けるのはバンドの裾を背景に入れないため。バンドが密集していて背景帯が隣のバンドに重なる場合は、gap・height を変えるか手動背景 ROI を使い、理由を記録する |
| 負の S | 0 に丸めない | 丸めると平均が上に偏り、検出限界以下という情報が失われる |
| ROI の大きさ | 同じタンパク質・同じ画像内でそろえる | 背景推定の誤差は ROI の画素数 N 倍で S に入るため（`docs/theory_ja.md` 3.4 節） |
| 技術的反復 | 平均してから生物学的反復として扱う | 技術的反復を独立な n に数えると、n を水増しして p 値が小さくなりすぎる |
| fold の基準 | 対照群の生物学的反復の値の算術平均（log2 を使う場合は対照群の幾何平均） | 計算の段階を明確にし、対照群の平均がちょうど 1 になるようにする |
| 統計 | 2 群：Welch の t 検定。3 群以上：Welch ANOVA ＋ Games–Howell（等分散を仮定しない） | 小さな n で等分散を確かめるのは難しく、等分散を仮定しないほうが安全側 |
| 比の対数変換 | 既定はしない（log2 は選択可） | 変換するかどうかはデータを見る前に決めるべきで、ツールが自動で選ぶべきではない。0・負の比は擬似値で置き換えず、log2 では検定しない |
| エラーバー | SD（個々の点と一緒に表示） | データのばらつきをそのまま示す。SEM・95%CI を使う場合は図の説明に明記する |
| bit 深度 | 同じ実験の画像はそろえる | 8-bit と 16-bit の値は階調スケールが違い、直接比較できない（混在すると本アプリは統計と Figure を止める） |
| OD 変換 | しない | 透過モード・較正なしでは OD を正しく計算できない（`docs/theory_ja.md` 9 節） |
| 膜間の比較 | 行わない（警告のみ） | 膜・露光が違う生の値は直接比べられない。共通参照レーンによる膜間正規化は未実装 |

## 4. 結果の記録と報告

### 4.1 保管するもの

- 原画像（スキャンしたままの TIFF）と、その SHA-256。
- プロジェクトファイル（ROI 座標、背景法、設定、QC 判断、履歴を含む）。
- 出力一式（測定 CSV、ROI 一覧、設定 JSON、正規化結果、ROI オーバーレイ画像、統計結果、Figure と説明文、複合 Figure の切り出し記録）。
- 使わなかった露光の画像も消さずに残します。

### 4.2 報告（論文・発表・ノート）に書く項目

1. **画像取得**：フィルムの種類、露光時間（定量に使った露光）、スキャナー機種、透過/反射、グレースケール、bit depth、解像度、自動補正をオフにしたこと。
2. **定量方法**：使用ソフトウェアとバージョン、矩形 ROI による背景補正積分であること、式 `S = s · (Σp − N·b)`、ROI の大きさ（画素数）、背景法とパラメータ（例：バンドと同じ幅の上下の帯、高さ ○ px・間隔 ○ px（バンド ROI の高さの ○%））。
3. **値の性質**：較正されていない相対的な画像強度であること（OD やタンパク質量ではない）。
4. **線形範囲**：希釈系列などで線形範囲を確認したかどうか。未確認ならその旨。
5. **正規化**：分子と分母（例：pERK / actin、pERK / total ERK）、ローディングコントロールの取得方法（再プローブ／膜の切り分け／別の膜）、分子と分母が同じ膜か別の膜か、対照群を1とした相対値の基準（対照群の算術平均、または log2 の場合は幾何平均）、計算の段階。
6. **反復と統計**：生物学的反復の数（各群の n）とその定義、技術的反復の扱い（平均してから解析）、対応のある設計なら対応の単位（subject_id）、使った検定（Welch の t 検定／対応のある t 検定／Welch ANOVA ＋ Games–Howell／一元配置 ANOVA ＋ Dunnett・Tukey）と多重比較の調整、効果量、95% 信頼区間、p 値（調整済みか）、対数変換の有無、エラーバーの種類（SD／SEM／95%CI）。
7. **除外**：除外したバンド・試料と、その理由（事前に決めた基準）。
8. **QC**：飽和の疑いなどの警告にどう対応したか。
9. **画像の提示**：Figure のブロット画像に加えた処理（切り出し座標、表示レベル（線形）、明るさ・コントラストの調整は画像全体に一様にかけたか）、別の膜や別の露光を並べた場合はその境界を明示したこと。原画像を提出できるよう保管していること。

### 4.3 書いてはいけない表現の例

- 「タンパク質量が 2.1 倍に増加した」（較正と線形範囲の確認がない場合）→「相対強度（対照群を1とした相対値）が 2.1 倍」
- 「OD を測定した」（OD に変換していない場合）
- 「n = 6」（3 個体 × 技術的反復 2 回の場合）→ n = 3
- 「エラーバーは誤差」（種類を書かない）→「平均 ± SD」「平均 ± SEM」「平均と 95% 信頼区間」
- 「飽和していないことを確認した」（画素値の端値チェックだけの場合）→「画素値の端値（飽和の疑い）がないことを確認した」
