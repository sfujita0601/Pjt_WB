# 定量の理論（積分強度・背景補正・正規化・統計）

対象：本アプリ（`wbtool`）を使う学生・教員
対応する実装：`wbtool/core/quant.py`、`normalize.py`、`stats.py`、`stats_multi.py`、`stats_runner.py`、`figure.py`、`qc.py`、`lanes.py`、`wbtool/models/project.py`

このドキュメントの式と記号は実装と一致させています。式を変更する場合は、コードとこのドキュメントを同時に直してください。

> **最初に押さえる大前提**
> 本アプリが出す数値は、すべて**較正されていない「相対的な画像強度」**です。光学密度（OD）やタンパク質の量（ng など）ではありません。同じ画像の中、同じ条件でそろえて比べたときにだけ、相対的な比較に使えます。

---

## 1. 画像と座標の約束

- 画像は 2 次元のグレースケール配列として読み込みます。8-bit（0〜255）と 16-bit（0〜65535）は**元の値のまま**扱い、16-bit を 8-bit に縮小することはありません。
- カラー画像は `0.299R + 0.587G + 0.114B`（ITU-R BT.601）でグレースケールに変換し、元の型の範囲に丸めます。3 チャンネルが同じ値なら変換せずに 1 チャンネルを使います。カラーで取り込むことは推奨しません（`docs/protocol_ja.md`）。
- 座標は**原画像の画素座標**です。原点は左上、x は列（右に向かって増える）、y は行（下に向かって増える）で、すべて整数です。
- 矩形の測定領域（ROI：region of interest）は `Rect(x, y, w, h)` で表し、含まれる画素は列 `x 〜 x+w−1`、行 `y 〜 y+h−1` です。画素数は `N = w × h` です。
- 表示の拡大率、表示用の反転、コントラスト調整は ROI 座標にも測定値にも影響しません。測定には常に原画像の画素値を使います。
- ROI が画像の外にはみ出した場合は、画像内の部分だけを測定し、警告を出します。

## 2. 極性 s（バンドが暗いか明るいか）

フィルムをスキャンした画像では、ふつうバンドは背景より**暗い**（画素値が小さい）です。一方、反転済みの画像や蛍光画像ではバンドが**明るく**なります。そこで符号 s を次のように決めます。

| 極性（`polarity`） | 意味 | s |
|---|---|---|
| `dark`（初期値） | バンドが背景より暗い（フィルムのスキャン像） | −1 |
| `bright` | バンドが背景より明るい（反転済み・蛍光など） | +1 |

s があるので、どちらの画像でも「バンドが濃いほど S が大きい」という向きになります。

- 表示上の「反転」は見た目を変えるだけで、画素値も s も変わりません。数値を変えたいときは極性の設定を変えます。
- 極性を間違えると S の符号が逆になります（下の数値例では S = −228）。負の S が並んだら、まず極性設定を疑ってください。

## 3. 積分強度と背景補正（background subtraction）

### 3.1 定義

ROI 内の画素値を p_i（i = 1, …, N）、背景推定値を b（ROI 内では一定）、極性の符号を s とすると、背景補正後の積分値 S は次のとおりです。

```
S = Σ_i s · (p_i − b) = s · (Σ_i p_i − N · b)
```

本アプリはこの計算の途中の値をすべて別々に記録します（測定 CSV の列名）。

| 量 | 式 | 列名 |
|---|---|---|
| ROI の画素数 | N = w × h（画像内の部分） | `n_pixels` |
| 補正前の積分値 | raw_sum = Σ p_i | `raw_sum` |
| ROI の平均画素値 | raw_sum / N | `raw_mean` |
| 背景推定値 | b | `bg_value` |
| 背景の積分値 | bg_sum = N · b | `bg_sum` |
| 背景推定に使った画素数 | — | `bg_n_pixels` |
| 背景補正後の積分値 | S | `corrected` |

- **S が負になっても 0 に丸めません。** バンドが背景より弱い（検出限界以下）、背景の取り方がおかしい、極性が逆、のどれかの可能性があるので、QC で「注意」を出し、値はそのまま残します。
- 仕様書には `S = Σ s(p_i − b_i)` と書かれていますが、MVP の 3 方式ではどれも b が ROI 内で一定です。画素ごとに違う背景（傾斜背景の平面フィット、rolling ball など）は実装していません。

### 3.2 背景推定の 3 方式

背景推定法は画像ごとに設定し、バンドごとに上書きできます。

**(a) 同一レーンのバンド近傍（上下）`local`**（初期値）

- バンド ROI の上と下に、間隔 `gap` を空けて高さ `height` の帯を 1 本ずつ置きます。初期値は `gap = 3` px、`height = 5` px です。
- 帯の横の範囲は、**バンド ROI と同じ x と幅**です（レーン ROI の幅は使いません）。
  - 上の帯：`Rect(band.x, band.y − gap − height, band.w, height)`
  - 下の帯：`Rect(band.x, band.y + band.h + gap, band.w, height)`
- どちらの帯も画像内にクリップします。b は**2 本の帯に含まれる全画素の平均**です（画素数で重み付けした平均で、「帯ごとの平均の平均」ではありません）。
- 片方の帯が画像の外に出た場合は、残った片側だけで推定し、警告を出します。両方とも外なら b は未定義（NaN）になり、QC で「エラー」を出します。
- 上下の帯の高さが同じで、背景が y 方向に一様に傾いている（線形に変化する）場合は、上下の平均がバンド位置の背景にほぼ一致します。
- `gap` と `height` は px で保存されますが、**3 px・5 px は固定の標準値ではありません。** 同じバンドでも解像度が 2 倍なら画素数で 2 倍に写り、バンドの太さも実験ごとに違うからです。本アプリは、その画像のバンド ROI の高さ h（中央値）に対する比率（`gap / h`、`height / h`）を表示し、比率から px を設定する操作も用意しています（画面の初期値は gap 30%・height 50%。これは目安で、正解の値ではありません）。px への換算は `round(h × 比率)`（height は最小 1 px）です。比率で決めても、背景帯が隣のバンドや smear にかからないかは目で確認します。

**(b) 手動背景 ROI の平均 `manual_roi`**

- ユーザーが画像上に置いた背景 ROI（複数可）の**全画素の平均**を b とします。背景 ROI は画像単位で保存され、その画像で手動背景を使うすべてのバンドに同じ b が使われます。
- 背景 ROI が 1 つもない場合は b が未定義になり、QC で「エラー」を出します。

**(c) 背景補正なし `none`**

- b を「理論上の端の値」とします。
  - 暗いバンド（s = −1）では **b = dtype の最大値**（8-bit：255、16-bit：65535）、つまり「真っ白」を基準にします。このとき `S = Σ (max − p_i)` です。
  - 明るいバンド（s = +1）では b = 0 で、`S = Σ p_i` です。
- 背景の画素はバンドがなくても S に上乗せされます（暗いバンドなら 1 画素あたり `max − 背景値`）。ROI の大きさや背景の濃さに強く影響されるので、**比較・教育用**であり、標準の方法としては推奨しません。

いずれの方式でも、背景帯や背景 ROI がほかのバンド ROI と重なると、QC で「背景 ROI とバンドの交差」を警告します。

### 3.3 手で計算できる数値例

教材用の小さな 8-bit 画像（9 行 × 3 列）です。レーン ROI は画像全体 `Rect(0, 0, 3, 9)`、バンド ROI は `Rect(0, 3, 3, 2)`（行 3〜4、幅は画像幅と同じ 3 列）、極性は暗いバンドです。この例では近傍背景のパラメータを `gap = 1`、`height = 2` にしています（アプリの初期値は 3 と 5）。

```
 y \ x   0    1    2      行の合計
  0    202  200  198      600   ← 上の背景帯（y=0〜1）
  1    200  202  200      602   ←
  2    201  199  200      600     （gap）
  3    180  140  182      502   ← バンド ROI（y=3〜4）
  4    170  120  172      462   ←
  5    199  201  200      600     （gap）
  6    196  198  196      590   ← 下の背景帯（y=6〜7）
  7    198  196  198      592   ←
  8    197  197  197      591   ← 手動背景 ROI の例 Rect(0, 8, 3, 1)
```

**補正前の値**：N = 6、raw_sum = 502 + 462 = 964、raw_mean = 160.667

| 背景法 | b | bg_sum = N·b | S = −(964 − N·b) |
|---|---|---|---|
| (a) 近傍上下帯 | (600+602+590+592)/12 = 2384/12 = 198.667 | 1192 | **228** |
| (b) 手動背景 ROI `Rect(0,8,3,1)` | 591/3 = 197 | 1182 | **218** |
| (c) 補正なし（白 = 255 基準） | 255 | 1530 | **566** |

- 同じバンドでも、背景法によって S が 218〜566 と大きく変わります。**背景法は必ず記録し、比較するバンドどうしでそろえます。**
- 同じ画像を反転（255 − p）し、極性を `bright` にして近傍背景で測ると、b = 56.333、raw_sum = 566、S = +228 になり、(a) と一致します。補正なしで測ると b = 0、S = 566 で、(c) と一致します。
- 暗いバンドの画像を誤って `bright` として測ると、S = −228 になります。

（これらの値は `wbtool.core.quant` の関数で検算済みです。）

### 3.4 ROI サイズの影響

背景推定値 b に誤差 Δ（b = 真の背景 + Δ）があると、

```
S（推定） = S（真） − s · N · Δ
```

となり、**背景の誤差は ROI の画素数 N 倍になって S に入ります。** ROI を大きくすれば、そのぶん背景の誤差が拡大されます。

上の例でバンド ROI を上下 1 行ずつ広げ、`Rect(0, 2, 3, 4)`（N = 12、raw_sum = 2164）にすると次のようになります。

| 背景法 | ROI 高さ 2（N=6） | ROI 高さ 4（N=12） | 変化の理由 |
|---|---|---|---|
| (b) 手動背景（b = 197） | 218 | 200 | 追加した行（値 ≈ 200）が b より明るいので、1 画素あたり約 −3 ずつ S が減る |
| (c) 補正なし（b = 255） | 566 | 896 | 追加した 6 画素 × (255 − 200) = 330 がそのまま上乗せされる |

本物の画像でも同じことが起こります。合成画像 `examples/synthetic_simple_8bit.png`（背景 220、バンドの深さ 40/80/120/160、ROI 22×10 = 220 画素）では次のとおりです。

| バンド | S（近傍背景） | S（補正なし） | 差 = 220 × (255 − 220) |
|---|---|---|---|
| 1 | 8,800 | 16,500 | 7,700 |
| 2 | 17,600 | 25,300 | 7,700 |
| 3 | 26,400 | 34,100 | 7,700 |
| 4 | 35,200 | 42,900 | 7,700 |

真の比「バンド 4 ÷ バンド 1」は 4.0 ですが、補正なしだと 42,900 / 16,500 = 2.6 になり、差が縮んで見えます。

実務上の注意：

- 比較するバンドどうしは **ROI の幅と高さをそろえます**（タンパク質ごと・画像ごとに大きさが違うと QC で警告）。
- ROI はバンド全体を含み、なるべく余分な背景を含まない大きさにします。小さすぎてバンドの裾を切ると S を過小評価します。
- ROI どうしが重なると同じ画素を 2 回数えることになるので、QC で警告します。

### 3.5 レーンプロファイルとプロファイル面積（参考値）

- **レーンプロファイル**：レーン ROI 内の各行 y について、列方向の平均画素値を求めたものです（横軸 y、縦軸「行の平均画素値」）。
- **プロファイル面積**（`profile_peak_area`、参考値）：指定した範囲 y_start 〜 y_end−1 のプロファイル値 v_y について、範囲の**両端の 2 点を結ぶ直線**をベースライン base_y とし、

  ```
  面積 = Σ_y s · (v_y − base_y)
  ```

  を計算します。単位は「行平均画素値 × 行数」です。
- 上の 9×3 の例で y = 2〜5 を指定すると、v = 200, 167.33, 154, 200、ベースラインは 200 で一定なので、面積 = 32.67 + 46 = 78.67 です。
- この面積に**レーン幅を掛けると**矩形積分と同じ次元になりますが、ベースラインの決め方が違うので、一般には S と一致しません（この例では 78.67 × 3 = 236。近傍背景の S は 228）。合成画像のバンド 1 では、レーン幅 30 の面積 293.33 × 30 = 8,800 となり、背景が一様なので S と一致します。
- 定量の標準は**矩形 ROI の背景補正積分 S** です。プロファイル面積は、どこを積分しているかを理解するための補助表示です。ImageJ の Gel Analyzer のピーク面積と考え方は似ていますが、同じ値になるとは限りません（`docs/validation_imagej.md`）。

### 3.6 レーン位置の候補提示

レーン候補は、指定範囲の各列の平均値に s を掛け、平滑化してピークを探して求めます。指定した数のピークが見つからなければ等間隔に配置します。どちらの場合も**候補にすぎない**ので、必ず目で確認し、ドラッグで修正してください。バンドの自動検出は行いません。

## 4. 正規化と対照群を1とした相対値（fold change）

### 4.1 計算の段階

正規化は次の順序で行います（アプリの画面にも同じ順序で表示されます。実装は `normalize.py`）。

1. **① 試料ごとの比**：同じ `sample_id` のバンドどうしで
   `R = S(分子タンパク質) ÷ S(分母タンパク質)`
   例：分子 = Target（pERK など）、分母 = ローディングコントロール（loading control、actin など）や total タンパク質（phospho/total）。何を分子・分母にするかは毎回明示的に選びます。
2. **② 生物学的反復（biological replicate）の値**：同じ群・同じ `bio_rep` に属する技術的反復（technical replicate）の R を**算術平均**します。技術的反復は独立な n に数えません。
3. **③ 対照群を1とした相対値（fold）**：
   `fold = ②の値 ÷ （対照群の②の値の算術平均）`　… 表示用
4. **④ log2（選択時に検定・作図に使う）**：② の値が正のときだけ
   ```
   log2_ratio = log2(② の値)
   log2_fold  = log2_ratio − （対照群の log2_ratio の平均）
   fold_geo   = 2^log2_fold        … 対照群の幾何平均を 1 とした相対値
   ```

計算しないケース（黙って続けない）：

- 分母が 0 以下・欠損・NaN → その試料の比は計算しません（status 列に理由を表示）。
- 分子の S が NaN（背景を推定できない、ROI が画像外など）→ その試料の比は計算しません。比を計算できなかった試料は統計の注意と欠損数にも表示されます。
- 同じ sample_id に同じタンパク質のバンドが 2 つ以上ある（同じ膜の別露光を両方「定量に使う」にしているなど）→ 重複として計算しません。
- 分子が 0 以下 → 比は計算しますが「注意」を表示します（④ の log2 は計算しません）。
- `bio_rep` が空の試料は②以降の集計から外します。
- 対照群の平均比が 0 以下、または対照群に有効なデータがない → fold を計算しません。対照群に log2 変換できない値がある → log2_fold を計算しません。
- 分子と分母が別の膜、または分子が複数の膜にまたがる → 警告を出します（膜間正規化は未実装です）。
- 同じタンパク質の値が 8-bit と 16-bit の画像から混在する → **統計と Figure を止めます**（4.6 節）。

### 4.2 数値例

| sample_id | 群 | bio_rep | tech_rep | S(pERK) | S(actin) | ① R | 試料単位の fold |
|---|---|---|---|---|---|---|---|
| S1 | Control | R1 | T1 | 1000 | 2000 | 0.50 | 0.909 |
| S2 | Control | R2 | T1 | 1200 | 2000 | 0.60 | 1.091 |
| S3 | Control | R2 | T2 | 900 | 1500 | 0.60 | 1.091 |
| S4 | Treated | R1 | T1 | 2400 | 2000 | 1.20 | 2.182 |
| S5 | Treated | R2 | T1 | 3300 | 2200 | 1.50 | 2.727 |

② 生物学的反復へ集約（S2 と S3 は同じ Control/R2 の技術的反復）：

| 群 | bio_rep | n_tech | ② R | ③ fold |
|---|---|---|---|---|
| Control | R1 | 1 | 0.50 | 0.50 / 0.55 = 0.909 |
| Control | R2 | 2 | (0.60 + 0.60)/2 = 0.60 | 1.091 |
| Treated | R1 | 1 | 1.20 | 2.182 |
| Treated | R2 | 1 | 1.50 | 2.727 |

対照群の平均 = (0.50 + 0.60)/2 = 0.55 です。対照群の n は 2 で、3 ではありません。

- 対照群の平均は②の値（生物学的反復）から計算するので、対照群の fold の平均はちょうど 1 になります。
- 「試料単位の fold」は試料の表で確認するための値で、統計には②以降の生物学的反復単位の値を使います。
- 全員を同じ定数（対照群の平均）で割るだけなので、fold で検定しても比で検定しても p 値は同じです（平均差と信頼区間は定数倍になります）。そのため本アプリでは、検定に使う値は「正規化比」か「log2（正規化比）」から選びます。

### 4.3 ローディングコントロールで割ることの前提（線形性）

`R = S_T / S_LC` が「ロード量の違いを打ち消した値」になるのは、次の条件がそろうときだけです。

```
S_T  = k_T  × （Target の量）      … 原点を通る比例関係
S_LC = k_LC × （ローディングコントロールの量）
```

この比例関係は、抗体・露光・フィルム・スキャナーのすべてを含めて**測定範囲内で成り立つ**必要があります。ローディングコントロール（actin、GAPDH など）は量が多いので、Target より先に飽和しやすいことが知られています。

架空の例：ロード量が 1.0 と 1.5 の 2 レーンで、Target の量の割合は同じとします。Target は比例して 1000 → 1500 になりますが、actin は飽和して 2000 → 2200（比例なら 3000）にしかならないとします。すると R = 0.50 → 0.68 となり、実際には変化がないのに **1.36 倍に増えたように見えます**。

- 線形性は画像の画素値からは証明できません。**希釈系列や露光時間を変えた比較で実験的に確かめる**必要があります（線形範囲の QC 機能は未実装です）。
- 分母のばらつき（ロード量の違い）が大きいほど、分母の誤差が比に大きく影響します。
- phospho / total のような比は、どちらも同じ前提を満たす必要があります。
- ローディングコントロールの取得方法（同じ膜の再プローブ、膜を切り分けて別々に検出、別の膜に同じ試料を流す、など）は実験によって違います。本アプリはどの場合も sample_id で対応付けますが、**分子と分母が別の膜**だと膜ごとの転写効率・露光の違いが補正されないため、「対応付けはできるが、正規化として適切とは限らない」と警告します。

### 4.4 対照群の平均で割ることの注意

- ③ の fold は「対照群の平均」という**データから推定した値**で割っています。対照群の各値も同じ基準で割られるので、**対照群の fold は 1 の周りにばらつきます**（平均がちょうど 1 になるだけです）。
- したがって、対照群を「誤差のない 1」として描いたり、処理群の fold を定数 1 と比べる 1 標本 t 検定をしたりしてはいけません。対照群の値のばらつきを無視することになり、p 値が小さくなりすぎます。本アプリの Figure は対照群の点とエラーバーも描き、検定は対照群の値を含めて行います。
- 基準値は全群に共通なので、③ の割り算は群間の検定結果を変えません（p 値は比と同じ）。一方、fold の絶対値（「2.5 倍」など）は基準値の推定誤差を含みます。対照群の n が小さいと、基準値そのものが不安定になります。
- 対照群に 0 に近い値や外れ値があると、算術平均で割った fold が大きく変わります。④ の log2_fold（対照群の幾何平均を基準）は外れ値の影響が比較的小さいですが、どちらを使うかは**データを見る前に**決めます。

### 4.5 log2 変換（④）

**定義**（② の値 R_j が正のときだけ計算）：

```
log2_ratio_j = log2(R_j)
m0           = 対照群の log2_ratio の算術平均
log2_fold_j  = log2_ratio_j − m0
fold_geo_j   = 2^(log2_fold_j)
```

`2^m0` は対照群の比の**幾何平均**なので、fold_geo は「対照群の幾何平均を 1 とした相対値」です。③ の fold（対照群の**算術平均**を 1 とした相対値）とは基準が違います。

**算術平均と幾何平均の違い**：比のように倍率で効く量では、2 倍と 1/2 倍は log2 で +1 と −1 になり、対称に扱えます。算術平均は大きい値に引っ張られます。

数値例（**教材用合成データ**。値は `wbtool.core.normalize.normalize` で検算済み）：

| 群 | bio_rep | ② R | ③ fold | log2_ratio | log2_fold | fold_geo |
|---|---|---|---|---|---|---|
| Control | C1 | 0.400 | 0.787 | −1.322 | −0.322 | 0.80 |
| Control | C2 | 0.500 | 0.984 | −1.000 | 0.000 | 1.00 |
| Control | C3 | 0.625 | 1.230 | −0.678 | +0.322 | 1.25 |
| Treated | T1 | 0.800 | 1.574 | −0.322 | +0.678 | 1.60 |
| Treated | T2 | 1.000 | 1.967 | 0.000 | +1.000 | 2.00 |
| Treated | T3 | 2.000 | 3.934 | +1.000 | +2.000 | 4.00 |

- 対照群の算術平均 = 0.5083、幾何平均 = 2^(−1.000) = 0.500。
- 群の比べ方による「何倍か」の違い：算術平均の比 = 1.2667 ÷ 0.5083 = **2.49 倍**、幾何平均の比 = 2^(log2 の平均差 1.226) = **2.34 倍**。
- Welch の t 検定：比（線形）で p = 0.174（t = 2.01、自由度 2.12）、log2_ratio で p = 0.073（t = 2.79、自由度 2.83）。

**検定値と表示値の区別**：

- 検定に使う値は「正規化比」か「log2（正規化比）」です。log2_fold・fold_geo は log2_ratio から定数を引いただけなので、検定結果は log2_ratio と同じです。
- 図の縦軸には fold・log2_fold・fold_geo などを選べますが、**検定に使った値とスケール（線形／log2）が違う場合は**画面に警告が出て、説明文には検定に使った値が書かれます。
- log2 スケールの差 d は、`2^d` が群間の幾何平均の比になります（画面に「倍率」として併記）。
- 上の例のように、線形と log2 で p 値は変わり得ます。**どちらで解析するかはデータを見る前に決め**、p 値が小さい方を後から選んではいけません。log2 は既定ではありません。

**0・負の値は変換しない**：比が 0 以下（分子の S が 0 以下）や欠損の生物学的反復は、log2 変換せずに `log2_status` 列に理由を表示します。0.001 や最小値の半分などの**擬似値に置き換えて log を取ることはしません**。置き換える値の選び方で結果が大きく変わり、検出限界以下という情報が失われるためです。log2 で検定しようとしたときにこのような値があると、検定を行わず、線形スケールで解析するか測定（背景・極性）を見直すよう表示します。

### 4.6 8-bit と 16-bit を直接比較しない理由

- 8-bit 画像の画素値は 0〜255、16-bit 画像は 0〜65535 です。同じバンドでも、S の値のスケールがまったく違います。
- 単純に 257 倍（または 256 倍）すれば換算できるとは限りません。スキャナーが 8-bit で出力するときに、ガンマ補正やレベル調整、端の切り詰めをどう行ったかは画像からは分からず、対応が線形である保証がないためです。
- したがって、**同じタンパク質の値が 8-bit と 16-bit の画像から混在する場合**（例：Control は 16-bit、Treated は 8-bit で取り込んだ）、本アプリは正規化の結果に「統計と Figure を止める問題」を出し、統計・Figure・一括出力の図を作りません。
- 分子がすべて 16-bit・分母がすべて 8-bit のように、**全試料で同じ組み合わせ**の場合は止めません。比の絶対値は階調スケールに依存しますが、対応が線形なら共通の定数倍になり、対照群を 1 とした相対値では打ち消されるためです（その旨の注意を表示します）。ただし線形性は画像からは保証できないので、取り込みは同じ bit 深度にそろえるのが原則です。

## 5. 生物学的反復と技術的反復、実験単位ID

- **生物学的反復（biological replicate、`bio_rep`）**：独立に準備した試料（別の個体、別の日に独立に行った培養・処理など）。**統計の独立な単位（n）**です。`bio_rep` は群の中で一意にします。
- **技術的反復（technical replicate、`tech_rep`）**：同じ試料を繰り返しロードしたもの、同じ試料を繰り返し測ったものなど。測定のばらつきは減らせますが、n は増えません。本アプリでは②で平均してから統計に渡します。
- **同じ膜の別露光**は反復ではありません。飽和していない露光を 1 枚だけ「定量に使う」にします（複数を選ぶと QC で警告）。
- **実験単位ID（`subject_id`）**：同じ個体・同じ試料を**複数の条件で測った**ときに、その条件をまたいで共通にする ID です。対応のある検定は `subject_id` で対を作ります。
  - 例：マウス Mouse01 の処理前と処理後 → 両方の生物学的反復に `subject_id = Mouse01`。
  - **同じ日に測った・同じブロットに載せたというだけでは、同じ `subject_id` にしません。** そのような「まとまり」は `batch_id`（記録用）に書きます。
  - 群ごとに別の個体を使う独立な設計では空欄で構いません。
  - 同じ生物学的反復の中で `subject_id` が複数あると、試料表の確認を促す注意が出ます。
- `bio_rep` が空の行があると、独立な単位が分からないので**検定を行いません**。

## 6. 統計

解析の単位は生物学的反復の値（②の比、または④の log2_ratio）です。差は常に **B − A**（3群以上の比較表では、対照群との比較なら「処理群 − 対照群」）です。手法は［統計］画面の質問（何を比べたいか、独立か対応ありか、分散の仮定）で決まります（`stats_runner.py`）。

### 6.1 記述統計

各群について n、平均 x̄、標準偏差 SD（不偏、ddof = 1）、SEM = SD/√n、中央値、最小値、最大値を出します。平均の 95% 信頼区間は

```
x̄ ± t(0.975, n−1) × SD / √n
```

です（n ≥ 2 のときのみ）。

### 6.2 Welch の t 検定（独立な 2 群、等分散を仮定しない）

```
差      d̄  = x̄_B − x̄_A
標準誤差 SE = √( s_A²/n_A + s_B²/n_B )
t       = d̄ / SE
自由度   ν  = (s_A²/n_A + s_B²/n_B)² / [ (s_A²/n_A)²/(n_A−1) + (s_B²/n_B)²/(n_B−1) ]   … Welch–Satterthwaite
95%CI   = d̄ ± t(0.975, ν) × SE
```

効果量は **Hedges の g**（プール SD を使い、小標本補正あり）です。

```
s_p = √( ((n_A−1)s_A² + (n_B−1)s_B²) / (n_A + n_B − 2) )
d   = d̄ / s_p
J   = 1 − 3 / (4(n_A + n_B) − 9)
g   = J × d
```

注意：検定は等分散を仮定しませんが、g の分母はプール SD です。分散が大きく違う群では g の解釈に注意してください。

- 各群に n ≥ 2 が必要です。両群とも分散が 0 なら検定しません。n < 3 の群があると「きわめて不安定」と表示します。
- 両群に同じ `subject_id` があると、「同じ個体・試料を両条件で測った設計なら対応のある t 検定が適切」と注意を出します。

### 6.3 対応のある t 検定

両群に共通する `subject_id` k について、差 d_k = B_k − A_k（k = 1, …, n）を使います。

```
d̄  = 差の平均,  s_d = 差の SD（ddof = 1）
t   = d̄ / (s_d / √n),   自由度 n − 1
95%CI = d̄ ± t(0.975, n−1) × s_d / √n
効果量 d_z = d̄ / s_d   （小標本補正なし）
```

- 対応のある検定には、比較する両群のすべての行に `subject_id` が必要です。1 行でも空なら検定しません。
- 同じ群の中で `subject_id` が重複していると検定しません（1 つの群で 1 つの実験単位は 1 回だけ測る前提）。
- 片方の群にしかない `subject_id`（対が揃わないもの）は除外して、その数を表示します。対が 2 組未満、または差の SD が 0 なら検定しません。

### 6.4 2 群の数値例

値（教材用合成データ）：Control = 0.90, 1.00, 1.10、Treated = 1.60, 2.00, 2.70（各 n = 3）

- 記述統計：Control 平均 1.00、SD 0.10、95%CI [0.752, 1.248]。Treated 平均 2.10、SD 0.557、95%CI [0.717, 3.483]。
- **Welch**：d̄ = 1.10、SE = √(0.01/3 + 0.31/3) = 0.3266、t = 3.368、ν = 2.129、p = 0.0715、95%CI [−0.227, 2.427]。
  s_p = √((2×0.01 + 2×0.31)/4) = 0.40、d = 2.75、J = 1 − 3/(24 − 9) = 0.80、**g = 2.20**。
- **対応 t**（同じ順に同じ subject_id の対だった場合）：差 = 0.70, 1.00, 1.60、d̄ = 1.10、s_d = 0.458、t = 4.158、自由度 2、p = 0.0533、95%CI [−0.038, 2.238]、**d_z = 2.40**。

効果量は大きいのに、n = 3 では信頼区間が広く 0 をまたぎます。**p 値だけでなく、効果量・信頼区間・n・個々の点を一緒に示してください。**

### 6.5 3 群以上で多重比較が必要な理由

3 群（Control・DrugA・DrugB）を 2 群ずつ t 検定すると 3 回の検定になります。1 回ごとの有意水準を 0.05 にすると、「本当はどこにも差がないのに、少なくとも 1 回は有意になる」確率（familywise error rate）は、検定が独立と仮定した目安で

```
1 − (1 − 0.05)^3 = 0.143
```

と、0.05 の約 3 倍になります（実際の検定は互いに独立ではないので、正確な値は異なります）。群が増えるほど悪化します。そこで、比較の「族」全体で第一種の過誤を 0.05 に保つように p 値を**調整**します（調整済み p、`p_adj`）。

本アプリの 3 群以上の比較は次の 2 段構えで表示します。

1. **全体検定**（一元配置 ANOVA または Welch ANOVA）：「どこかの群の平均が違うか」。
2. **多重比較**（Tukey、Dunnett、Games–Howell）：「どの対が違うか」を、多重性を調整した p 値と同時 95% 信頼区間で示す。

多重比較の結果は全体検定の p 値に関係なく表示します。事前に決めた比較（「処理群を対照群と比べる」など）の結果を報告してください。全体検定が有意になってから比較を選ぶ、という使い方は勧めません。

### 6.6 一元配置 ANOVA（等分散を仮定）と η²

群 j = 1, …, k、群 j の n_j 個の値 x_ij、群平均 x̄_j、全体平均 x̄、N = Σ n_j とします。

```
SS_between = Σ_j n_j (x̄_j − x̄)²
SS_within  = Σ_j Σ_i (x_ij − x̄_j)²
SS_total   = SS_between + SS_within
MSE        = SS_within / (N − k)          … 群内の分散のプール推定
F          = [SS_between / (k − 1)] / MSE
自由度      (k − 1, N − k)
η²         = SS_between / SS_total
```

- **前提**：各群の値が互いに独立、各群がおおむね正規分布、**各群の分散が等しい**。
- **η²（イータ二乗）**は、全体のばらつきのうち群の違いで説明される割合（0〜1）です。参考値として表示します。n が小さいと母集団の値より大きめに出やすい点に注意してください。Welch ANOVA を選んだときも、η² は上の式で計算した参考値です。

### 6.7 Welch の一元配置 ANOVA（等分散を仮定しない）

```
w_j   = n_j / s_j²                        （s_j²：群 j の不偏分散）
x̄_w   = Σ w_j x̄_j / Σ w_j
A     = Σ w_j (x̄_j − x̄_w)² / (k − 1)
λ     = Σ (1 − w_j / Σ w)² / (n_j − 1)
B     = 1 + 2(k − 2) / (k² − 1) × λ
F     = A / B
自由度 df1 = k − 1,  df2 = (k² − 1) / (3λ)
```

- **前提**：独立性、各群がおおむね正規分布。等分散は仮定しません。各群の n が小さいと検出力が低くなります。
- 分散が 0 の群があると計算できないので、検定しません。
- 本アプリの既定（「等分散を仮定する」をオフ）です。小さな n で等分散を確かめるのは難しいためです。

### 6.8 Tukey（Tukey–Kramer）：全群間の比較、等分散を仮定

全ての対 (i, j) について、ANOVA の MSE を使います。群の n が違っても使える形（Tukey–Kramer）です。

```
SE_ij = √( MSE/2 × (1/n_i + 1/n_j) )
q     = |x̄_j − x̄_i| / SE_ij
p_adj = P( Q(k, N−k) ≥ q )                   … Q：スチューデント化された範囲の分布
同時 95%CI = (x̄_j − x̄_i) ± q_0.95(k, N−k) × SE_ij
```

- 前提は一元配置 ANOVA と同じ（等分散を含む）。
- 対照群との比較だけが目的なら、Dunnett の方が比較の数が少ないぶん検出力が高くなります。

### 6.9 Dunnett：対照群との比較、等分散を仮定

処理群 j と対照群 0 の各対について、

```
t_j   = (x̄_j − x̄_0) / √( MSE × (1/n_j + 1/n_0) )      自由度 N − k
```

p_adj と同時信頼区間は、k − 1 個の t_j の**同時分布**（相関のある多変量 t 分布）から求めます。本アプリは SciPy の `dunnett` を使い、多変量 t 分布の数値積分（準モンテカルロ法、誤差は 1e-4 程度）で計算します。同じ入力で同じ結果になるよう、乱数の種を固定しています。

- 前提は一元配置 ANOVA と同じ（等分散を含む）。
- 処理群どうしの比較は行いません。

### 6.10 Games–Howell：等分散を仮定しない多重比較

各対 (i, j) について、Welch の t 検定と同じ標準誤差と自由度を使い、スチューデント化された範囲の分布で調整します。

```
SE_ij = √( s_i²/n_i + s_j²/n_j )
t_ij  = (x̄_j − x̄_i) / SE_ij
ν_ij  = (s_i²/n_i + s_j²/n_j)² / [ (s_i²/n_i)²/(n_i−1) + (s_j²/n_j)²/(n_j−1) ]
p_adj = P( Q(k, ν_ij) ≥ |t_ij| × √2 )
同時 95%CI = (x̄_j − x̄_i) ± q_0.95(k, ν_ij) / √2 × SE_ij
```

- 前提：独立性、各群がおおむね正規分布。等分散は仮定しません。
- **対照群との比較で等分散を仮定しない場合**：Dunnett の不等分散版は実装していないため、Games–Howell を使い、**対照群を含む対だけを表示**します。調整は k 群すべての対（族の大きさ k(k−1)/2）について行うので、対照群との対だけを調整する場合より p 値が大きめになります（**保守的**）。

### 6.11 手法の使い分け

| 目的 | 等分散を仮定する | 等分散を仮定しない（既定） |
|---|---|---|
| 2 群・独立 | （Welch のみ実装） | Welch の t 検定 |
| 2 群・対応あり（subject_id） | 対応のある t 検定 | 同左 |
| 3 群以上・対照群と比較 | 一元配置 ANOVA ＋ Dunnett | Welch ANOVA ＋ Games–Howell（対照群を含む対のみ表示） |
| 3 群以上・全群間 | 一元配置 ANOVA ＋ Tukey（Tukey–Kramer） | Welch ANOVA ＋ Games–Howell |
| 3 群以上・対応あり（反復測定） | 未実装（検定しない） | 未実装（検定しない） |

- 何を比べるか（対照群とだけ／全ての対）は**実験の目的で事前に**決めます。結果を見てから p 値が小さい方を選んではいけません。
- 等分散を仮定するかどうかも事前に決めます。仮定すると群内分散をプールして自由度が大きくなるので、分散が本当に等しければ検出力が上がりますが、分散が違うと誤った結論になり得ます。
- 3 群以上の**独立群**の比較で、同じ `subject_id` が複数の群にある場合（同じ個体を複数条件で測った反復測定のデザイン）は、独立群の ANOVA に流し込まず検定しません。反復測定 ANOVA・混合効果モデルは未実装です。

### 6.12 3 群の数値例

値（教材用合成データ）：Control = 0.90, 1.00, 1.10、DrugA = 1.20, 1.50, 1.80、DrugB = 1.60, 2.00, 2.40（各 n = 3）。
群平均 1.0、1.5、2.0、不偏分散 0.01、0.09、0.16（分散が最大 16 倍違う）。
（数値は `wbtool.core.stats_multi` の関数で検算済み）

**一元配置 ANOVA**：SS_between = 3 × (0.5² + 0² + 0.5²) = 1.50、SS_within = 0.02 + 0.18 + 0.32 = 0.52、MSE = 0.52/6 = 0.0867、
F(2, 6) = 0.75 / 0.0867 = 8.654、p = 0.0171、η² = 1.50 / 2.02 = 0.743。

**Welch ANOVA**：w = 300、33.33、18.75、x̄_w = 1.1006、A = 11.760、λ = 0.8689、B = 1.2172、
F(2, 3.07) = 9.662、p = 0.0474。

**多重比較**（差 = B − A、95%CI は同時信頼区間）：

| 比較 | 差 | Tukey：95%CI / p_adj | Dunnett：95%CI / p_adj | Games–Howell：95%CI / p_adj | 参考：調整なしの Welch t の p |
|---|---|---|---|---|---|
| DrugA − Control | 0.5 | [−0.238, 1.238] / 0.174 | [−0.188, 1.188] / 0.140 | [−0.390, 1.390] / 0.166 | 0.090 |
| DrugB − Control | 1.0 | [0.263, 1.738] / 0.014 | [0.312, 1.688] / 0.011 | [−0.247, 2.247] / 0.079 | 0.042 |
| DrugB − DrugA | 0.5 | [−0.238, 1.238] / 0.174 | （比較しない） | [−0.567, 1.567] / 0.308 | 0.164 |

読み取れること：

- 調整なしの Welch t（2 群ずつ）では DrugB − Control が p = 0.042 ですが、Games–Howell で多重性を調整すると p = 0.079 になります。
- 等分散を仮定する Tukey・Dunnett では p = 0.014・0.011 と小さくなります。群内分散をプールして自由度 6 で評価するためです。しかしこの例の分散は最大 16 倍違うので、等分散の仮定は疑わしいと考えるべきです。**どの手法を使うかで結論が変わり得るので、データを見る前に決めておきます。**
- Dunnett は対照群との 2 対だけを調整するので、全 3 対を調整する Tukey より信頼区間が狭くなります。

### 6.13 前提と限界

- 独立性：生物学的反復が互いに独立であること。対応のある 2 群では、対応を `subject_id` で正しく指定すること。
- 正規性：各群（対応 t では差）がおおむね正規分布に従うこと。n が小さいと確かめるのは困難なので、すべての点を図示して外れ値を確認します。
- 比（ratio・fold）は右に裾を引く分布になりやすいです。log2 変換をするかどうかは**データを見る前に**決めておきます（4.5 節）。
- 二要因 ANOVA、反復測定 ANOVA、混合効果モデル、ノンパラメトリック検定は**未実装**です。対応のある 3 群以上のデザインは検定しません。

## 7. エラーバー：SD・SEM・95% 信頼区間

| 種類 | 式（平均 x̄ からの片側の幅） | 何を表すか | n を増やすと |
|---|---|---|---|
| SD（標準偏差） | `SD = √( Σ(x − x̄)² / (n − 1) )` | **データのばらつき**（個々の生物学的反復がどれだけ散らばるか） | 母集団の SD に近づく（小さくなるとは限らない） |
| SEM（標準誤差） | `SD / √n` | **平均の推定精度** | √n に反比例して小さくなる |
| 95% 信頼区間 | `t(0.975, n − 1) × SD / √n` | 平均の区間推定（同じ手順を繰り返すと 95% の区間が真の平均を含む） | 小さくなる。n が小さいと t が大きいので広い |

数値例（教材用合成データ、Control = 0.90, 1.00, 1.10、n = 3。`wbtool.core.figure.error_half_width` で検算済み）：

```
SD  = 0.100
SEM = 0.100 / √3 = 0.0577
95%CI の幅 = t(0.975, 2) × SEM = 4.303 × 0.0577 = 0.248   → [0.752, 1.248]
```

同じ SD 0.100 で n = 12 なら、SEM = 0.0289、95%CI の幅 = 2.201 × 0.0289 = 0.0635 です。

- n = 3 では SEM のバーは SD の約 0.58 倍、95%CI のバーは SD の約 2.5 倍の長さになります。**同じデータでも、どれを描くかで見た目がまったく違う**ので、図の説明に必ず種類を書きます（本アプリは説明文に自動で入れます）。
- 「群の違いを見せたい」ときに SEM を選んで差を大きく見せるのは誤解を招きます。本アプリの既定は SD で、常に個々の点を一緒に描きます。
- エラーバーが重なる・重ならないは、検定の有意・非有意と一対一には対応しません。検定結果は検定で示します。
- 箱ひげ図を選んだ場合、説明文には「中央値と四分位範囲（箱）」と書かれます。

## 8. 画像から分からないこと

本アプリの QC は「疑い」を示すだけで、確定診断はしません。

| 項目 | 画像から分かること | 画像だけでは分からないこと |
|---|---|---|
| 飽和 | 画素値が端の値（暗いバンドなら 0、明るいバンドなら最大値）に達した画素の数。画像全体で端値画素が 0.1% を超えると警告し、バンド ROI 内に 1 画素でも端値があると警告する | 端値に達していなくても、フィルム自体が飽和して濃度が頭打ちになっている場合は検出できない |
| フィルムの非線形性 | なし | フィルムの濃度は露光量に比例せず、S 字型の特性曲線（H&D 曲線）を描く。低露光側（かぶり付近）と高露光側（肩）では応答が鈍る |
| スキャナー | 画像の bit depth、最大値（16-bit なのに最大値が 4095 以下なら 12-bit 取り込みの疑い） | ガンマ補正、自動レベル補正、ダイナミックレンジ、反射/透過モードの違いによる非線形な変換 |
| 線形範囲 | なし | 信号がタンパク質量に比例するか。希釈系列・露光比較で実験的に確かめる必要がある |
| 背景の妥当性 | 背景帯とバンド ROI の重なり | smear、ghost band、気泡、膜のしわが背景に入っているか（目で確認する） |

したがって、**較正なしの S や比は「相対的な画像強度」とその比**であり、「タンパク質量が 2.1 倍」とは言えません。報告では「相対強度」「対照群を1とした相対値（fold change）」と書き、線形範囲を確認したかどうかを明記します。

## 9. OD（光学密度）に変換しない理由

透過光で測る光学密度は `OD = log10(I0 / I)`（I0：入射光、I：透過光）です。画素値の対数を取れば「OD らしい値」は計算できますが、本アプリは自動変換を行いません。理由は次のとおりです。

1. **I0 と I の対応が分からない**：画素値が透過光量に比例するのは、透過モードで、ガンマ補正や自動補正を切り、スキャナーの応答が線形な場合に限られます。反射モードのスキャン（紙のような扱い）では OD の定義が成り立ちません。
2. **較正が必要**：正しい OD を得るには、濃度が既知のステップタブレットなどで較正曲線を作る必要があります（本アプリには較正機能がありません）。
3. **OD に変換してもタンパク質量にはならない**：フィルムの特性曲線は非線形なので、OD もタンパク質量に比例するとは限りません。
4. **数値的に不安定**：画素値が 0 に近いところでは対数が発散し、ノイズが拡大されます。
5. **取り違えの防止**：「log 変換したから OD＝物質量」という誤解を避けるため、生の画素値による相対強度に限定しています。4.5 節の log2 変換は、**正規化比**に対する統計上の変換であり、OD 変換とは別物です。

OD 変換・較正機能は**未実装**です。ImageJ には「Uncalibrated OD」という変換がありますが、これは式を当てはめるだけで、較正の代わりにはなりません。

## 10. まとめ（学生向けチェック）

- S は `s · (Σp − N·b)`。raw_sum、b、N、S を分けて記録する。
- 背景法と ROI サイズは S を大きく変える。比較するバンドどうしでそろえる。近傍背景の px は解像度とバンドの大きさに合わせて決める。
- 負の S は丸めない。極性・背景・検出限界を見直すサインと考える。
- 正規化は ① 試料ごとの比 → ② 技術的反復を平均 → ③ 対照群の平均で割る（表示用）→ ④ 必要なら log2、の順。
- n は生物学的反復の数。別露光や技術的反復は n に数えない。対応は subject_id で決める。
- 3 群以上は多重比較で p 値を調整する。手法・スケール（線形／log2）・比較の範囲はデータを見る前に決める。
- エラーバーの種類（SD・SEM・95%CI）を必ず明記する。
- 8-bit と 16-bit の値を混ぜて比べない。
- ローディングコントロールでの正規化は線形性が前提。画像からは証明できない。
- 数値は較正なしの相対的な画像強度。飽和・フィルム・スキャナーの限界を報告に書く。
