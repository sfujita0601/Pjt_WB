# 1. Western blot のバンド濃度と画素値

## (1) 何を理解するか

- フィルムの「黒さ」と、スキャン画像の「画素値」の関係を言葉で説明できる。
- 画素値は**較正されていない相対的な画像強度**であって、光学密度（OD）やタンパク質量そのものではないと理解する。
- 「スキャン（画像を取り込むこと）」と「測定（画素値から数値を計算すること）」を分けて考えられる。
- **表示の反転（Invert 表示）は測定値を変えない**こと、**極性設定はバンド強度 S の符号の定義を変える**ことを区別できる。

## (2) 導入

化学発光法の Western blot では、膜上の抗体に結合した酵素が光を出し、その光で感光フィルムが黒くなります。現像したフィルムをスキャナーで取り込むと、黒い部分ほど**画素値が小さい**（暗い）画像になるのが普通です。

ここで注意したいのは、私たちが最終的に知りたいのは「試料中のタンパク質量の相対的な違い」なのに、手元にあるのは「スキャナーが記録した数値の並び」だけだという点です。その間には少なくとも次の段階があります。

1. タンパク質量 → 抗体の結合量（抗体の親和性・飽和の影響を受ける）
2. 抗体の結合量 → 発光量（基質の量・反応時間の影響を受ける）
3. 発光量 → フィルムの黒さ（露光時間・フィルムの特性曲線の影響を受ける）
4. フィルムの黒さ → 画素値（スキャナーの方式・ゲイン・自動補正・bit 深度の影響を受ける）

画像解析ソフトが扱えるのは 4 の結果だけです。1〜3 の段階が比例関係にあるかどうかは、**画像からは確かめられません**。

## (3) 直感

- 透過光でフィルムを照らすと、黒い部分ほど光が通らない。スキャナーはその通った光の量を画素値にする。だから「黒いバンド＝小さな画素値」になる（このような画像を本アプリでは**暗いバンド**と呼ぶ）。
- 蛍光撮像や、反転処理済みの画像では、バンドが背景より**明るく**写る（**明るいバンド**）。
- 画面上で白黒を反転して見せる（Invert 表示）のは、見やすさのための**表示の変更**にすぎない。原画像の数値は変わらないし、測定は常に原画像の数値で行う。
- 一方、「この画像のバンドは暗いのか明るいのか」という**極性設定**は、「どちら向きの差をシグナルとみなすか」を決める。極性を取り違えると、S の符号が逆になる。

## (4) 数式・原理

本アプリの矩形の測定領域（ROI）による積分の定義（wbtool/core/quant.py と同じ）を示します。

```
ROI 内の画素値      p_i   (i = 1 … N、原画像の値)
背景推定値          b     (ROI 内で一定)
極性の符号          s     (暗いバンド: s = −1、明るいバンド: s = +1)

補正前積分値        raw_sum = Σ p_i
背景積分値          bg_sum  = N × b
背景補正後積分値    S = Σ s·(p_i − b) = s × (raw_sum − N × b)
```

- S が負になっても **0 に丸めません**（バンドが背景より弱い、あるいは背景や極性の設定が不適切というサインとして残します）。
- 背景補正（background subtraction）で「背景補正なし」を選んだ場合、暗いバンドでは b を **dtype の最大値**（8-bit なら 255、16-bit なら 65535）とします。つまり完全な白を基準に、そこからの暗さを合計します。明るいバンドでは b = 0 です。

画素値の範囲は bit 深度で決まります。

| 形式 | 取り得る値 | 段階数 |
|---|---|---|
| 8-bit | 0〜255 | 256 |
| 16-bit | 0〜65535 | 65536 |

本アプリは 16-bit 画像を勝手に 8-bit に縮小しません。

フィルムの濃度を表すのに光学密度 OD = log10(I0 ÷ I)（I0：入射光、I：透過光）という量が使われることがあります。しかし、一般的なスキャナーの画素値が透過光 I に比例している保証はなく、自動補正やガンマ補正がかかっていることもあります。本アプリは OD への自動変換を行わず、S を「相対的な画像強度」として扱います。

## (5) 具体例

**教材用合成データ**（実験由来ではありません）。8-bit、背景の画素値 220、バンド ROI は幅 22 × 高さ 10 = 220 画素、バンド内の画素値は一様に 180（背景より 40 暗い）とします。

**例 1：背景を正しく 220 と推定した場合（暗いバンド、s = −1）**

```
raw_sum = 180 × 220 = 39600
bg_sum  = 220 × 220 = 48400
S = −1 × (39600 − 48400) = 8800
```

**例 2：背景補正なし（b = 255）**

```
bg_sum = 255 × 220 = 56100
S = −1 × (39600 − 56100) = 16500
```

背景そのものの暗さ（255 − 220 = 35 を 220 画素分＝7700）まで S に含まれてしまいます（詳しくは 3 章）。

**例 3：極性を誤って「明るいバンド」（s = +1）にした場合、b = 220**

```
S = +1 × (39600 − 48400) = −8800
```

同じ画素、同じ背景なのに符号が逆になります。本アプリは 0 に丸めず −8800 と記録し、QC で「負の補正値」として注意を出します。

**例 4：Invert 表示に切り替えた場合**

画面上ではバンドが白く見えますが、測定に使う原画像の値は 180 と 220 のままです。極性設定が「暗いバンド」のままなら S = 8800 で変わりません。

**例 5：同じ合成バンドを 16-bit で表した場合**

背景 220 × 257 = 56540、バンドの深さ 40 × 257 = 10280 とすると、背景を正しく引いた S は 10280 × 220 = 2261600 です。数値は 8-bit の 257 倍ですが、バンド同士の**比**は同じです。S の絶対値は bit 深度や取り込み条件で変わるので、異なる画像の S を生の値のまま比べてはいけません。

| 条件 | b | S |
|---|---|---|
| 正しい背景、暗いバンド | 220 | 8800 |
| 背景補正なし、暗いバンド | 255 | 16500 |
| 正しい背景、極性を誤設定 | 220 | −8800 |
| Invert 表示のみ変更 | 220 | 8800 |

（数値は wbtool.core.synthetic.make_blot と wbtool.core.quant.measure_band で検算済み）

## (6) 小問

**問 1.** 8-bit のスキャン画像で、背景が 230、バンド ROI（100 画素）内の画素値が一様に 200 でした。極性は暗いバンドです。(a) 背景を 230 と推定したときの S、(b) 背景補正なしのときの S を求めなさい。

**問 2.** ある学生が「Invert 表示にしたらバンドが白くなったので、極性も『明るいバンド』に変えた」と言っています。原画像は変更していません。何が起こりますか。

**問 3.** 「画素値の合計が 2 倍だから、タンパク質量も 2 倍だ」という主張の問題点を、(2) の 1〜4 の段階を使って説明しなさい。

## (7) 解答・解説

**問 1.**

```
raw_sum = 200 × 100 = 20000
(a) S = −1 × (20000 − 230 × 100) = −1 × (20000 − 23000) = 3000
(b) S = −1 × (20000 − 255 × 100) = −1 × (20000 − 25500) = 5500
```

(b) には背景の暗さ（255 − 230 = 25 を 100 画素分＝2500）が上乗せされています。

**問 2.** Invert 表示は表示だけの変更なので、測定に使う原画像は暗いバンドのままです。そこで極性を「明るいバンド」（s = +1）に変えると、S の符号が逆になり、バンドが強いほど S が大きな負の値になります。極性は**原画像**でバンドが背景より暗いか明るいかで決めます。表示の見た目で決めてはいけません。

**問 3.** 画素値から確かめられるのは段階 4 の結果だけです。抗体の飽和（段階 1）、発光の頭打ち（段階 2）、フィルムの特性曲線の非線形性や飽和（段階 3）、スキャナーのガンマ補正（段階 4）があると、比例関係は崩れます。比例関係を主張するには、希釈系列などで**実験的に**線形範囲を確認する必要があります（6 章）。

**このアプリでの操作：** ［画像・試料情報］で画像ごとの極性（暗いバンド／明るいバンド）を確認します。Invert 表示を切り替えても ［背景補正・定量］の表の S が変わらないことを確かめてみましょう。
