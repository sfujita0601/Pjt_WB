# 3. 背景補正（background subtraction）

## (1) 何を理解するか

- 背景補正が「バンドの信号」と「膜・フィルム・スキャナー由来の土台」を分けるための操作だと理解する。
- 補正しない場合に、バンドどうしの**比**がどのように歪むかを具体的な数値で説明できる。
- 背景の測定領域（ROI）の置き場所によって S と比が変わることを知り、背景法を固定して記録する理由を説明できる。
- 近傍背景の間隔・高さを、px の固定値ではなく**バンドの大きさに対する相対的な大きさ**で考えられる。

## (2) 導入

フィルムのスキャン画像では、バンドのない部分も真っ白（255）ではありません。フィルムのベースの色、非特異的な抗体の結合、膜のむら、スキャナーの照明むらなどで、背景にもある程度の「暗さ」があります。しかもその暗さは場所によって違うことがよくあります（上が薄く下が濃い、端が濃い、など）。

バンドの S には、何もしなければこの背景の暗さが混ざります。背景補正とは、背景の値 b を推定して、各画素から差し引いてから合計することです。どこから b を推定するかで結果が変わるため、本アプリでは背景法を選んで固定し、方法・背景 ROI の座標・画素数を結果と一緒に保存します。

本アプリで選べる背景法：

| 背景法 | b の決め方 |
|---|---|
| 同一レーンのバンド近傍（上下） | バンド ROI と同じ x・幅で、ROI の真上と真下（間隔 gap、高さ height。新しい画像の初期値は gap = 3 px、height = 5 px ですが、固定の標準値ではありません。(4)・(5) の後半を参照）に置いた帯の全画素平均 |
| 手動背景 ROI の平均 | ユーザーが置いた背景 ROI（複数可）の全画素平均。同じ画像のすべてのバンドに共通の b |
| 背景補正なし | 暗いバンドでは b = dtype の最大値（8-bit なら 255）、明るいバンドでは b = 0 |

## (3) 直感

- 背景補正なしは「真っ白を基準に、どれだけ暗いか」を測ること。バンドの暗さに、背景の暗さ × 画素数が上乗せされる。上乗せ分はどのバンドにも同じだけ乗るので、**弱いバンドほど相対的に過大評価**され、バンド間の差が縮んで見える。
- 背景が場所によって違うとき、バンドの位置より**明るい**場所で b を取ると S は大きすぎ、**暗い**場所で取ると S は小さすぎになる（暗いバンドの場合）。
- バンドのすぐ上下で背景を取れば、その場所の背景に近い値になる。背景がまっすぐ（線形に）傾いているなら、上下の平均はバンド位置の背景にほぼ一致する。
- ただし背景帯にバンドの裾や隣のバンドが入り込むと、b が暗くなりすぎて S は**過小評価**される。
- 「3 px」は画像によって意味が違う。600 dpi で取り込めば、300 dpi のときと同じバンドが縦横 2 倍の画素数で写る。バンドの太さも実験ごとに違う。だから近傍背景の間隔・高さは、**バンドの高さに対して何割か**で考える方が、画像が変わっても同じ意味を保てる。

## (4) 数式・原理

```
S = s × (Σ p_i − N × b)          (暗いバンド: s = −1)
```

真の背景を b0、推定した背景を b とすると、暗いバンドでは

```
S(b) = S(b0) + N × (b − b0)
```

- b が b0 より 1 大きい（明るい側にずれる）と、S は N だけ大きくなる。
- 背景補正なし（b = 255）では、S には N × (255 − b0) が上乗せされる。
- 誤差 N × (b − b0) は**バンドの強さに関係なく一定**。だからバンド間の比が歪む。

近傍背景が線形の傾斜を打ち消す理由（背景が行 y に対して b0(y) = c + g × y と変化する場合）：

```
上の帯の平均 = c + g × (y_c − d)
下の帯の平均 = c + g × (y_c + d)
平均        = c + g × y_c       (y_c：バンドの中心行、d：中心から帯までの距離)
```

上下の帯が中心から同じ距離にあれば、傾き g の影響は打ち消されます。曲がった背景（非線形）やしみ・汚れは打ち消せません。

**近傍背景の相対的な大きさ**：本アプリは間隔と高さを px で保存しますが、バンド ROI の高さ h に対する比率でも表示・設定できます。

```
間隔の比率 = gap ÷ h          高さの比率 = height ÷ h
比率から設定する場合：gap = round(h × 間隔の比率)、height = round(h × 高さの比率)（最小 1 px）
h はその画像のバンド ROI の高さの中央値
画面の初期値：間隔 30%・高さ 50%（目安であり、正解の値ではない）
```

- gap は「バンドの裾を背景に入れない」ための余白、height は「背景の平均を安定させる」ための画素数です。どちらもバンドが大きければ大きく、小さければ小さくするのが自然です。
- 比率で決めても、隣のバンド・smear・汚れが背景帯に入らないかは、必ず画像とプロファイルで確認します。

S が負になった場合も 0 に丸めずに記録します。負の値は、バンドが検出限界以下か、背景・極性の設定が不適切であることを示す情報です。

## (5) 具体例

**教材用合成データ**（実験由来ではありません）。8-bit、背景の画素値は画像の上から下へ 1 行あたり 0.5 ずつ**増える**（中央の行で 200、上端で約 170、下端で約 230。つまり上ほど暗く、下ほど明るい）とします。バンドは 2 本、どちらも幅 22 × 高さ 10 = 220 画素で、同じ行（y = 55〜64）にあり、背景からの深さは 40 と 80。正解は S1 = 8800、S2 = 17600、**比 S2 ÷ S1 = 2.00** です。

背景法と背景 ROI の置き場所を変えると：

| 背景の取り方 | b | S1 | S2 | S2 ÷ S1 |
|---|---|---|---|---|
| 背景補正なし（b = 255） | 255 | 20944 | 29744 | 1.42 |
| 手動背景 ROI：画像の上端 10 行 | 172.2 | 2728 | 11528 | 4.23 |
| 手動背景 ROI：画像の下端 10 行 | 227.3 | 14850 | 23650 | 1.59 |
| 同一レーンのバンド近傍（上下） | 199.8 | 8800 | 17600 | 2.00 |
| 手動背景 ROI がバンドにかかった例 | 179.8 / 162.2 | 4400 | 9328 | 2.12 |

（数値は make_blot・estimate_background・measure_band で検算済み。b は画素値の丸めを含む実際の平均値）

読み取れること：

- **補正なし**：両方のバンドに 220 × (255 − 199.8) ≈ 12144 が上乗せされ、比は 2.00 から 1.42 に縮む。
- **上端で背景**：上端は暗いので b = 172.2 は小さすぎる（暗すぎる）。S が小さくなり、弱いバンドほど相対的に大きく削られて比は 4.23 に広がる。
- **下端で背景**：下端は明るいので b = 227.3 は大きすぎる（明るすぎる）。補正なしと同じ方向にずれる（比 1.59）。
- **近傍背景**：線形の傾斜なので上下平均がバンド位置の背景（199.8）と一致し、正解どおり。
- **バンドにかかった手動 ROI**：各バンドについて、そのレーンのバンド上端に重なる位置（幅 30 × 高さ 5、うち 3 行がバンドと重なる）に背景 ROI を置いた例。バンドの暗い画素が背景に混ざり、b が暗すぎて S が大幅に過小評価される。本アプリの QC は「背景 ROI とバンドの交差」として警告する。

**近傍背景の px を画像に合わせる例**（教材用合成データの想定。計算は上の式どおり）：同じ膜を 300 dpi と 600 dpi で取り込み、バンド ROI の高さがそれぞれ h = 10 px と h = 20 px になったとします。

| 取り込み | h | 固定値 gap 3 px・height 5 px の比率 | 比率 30%・50% から設定した px |
|---|---|---|---|
| 300 dpi | 10 px | 間隔 30%・高さ 50% | gap 3 px・height 5 px |
| 600 dpi | 20 px | 間隔 15%・高さ 25% | gap 6 px・height 10 px |

600 dpi の画像に 3 px・5 px をそのまま使うと、バンドの大きさに対して背景帯が半分の距離・半分の高さになり、ぼやけたバンドの裾が背景帯に入りやすくなります。比率で考えれば、どちらの画像でも「バンドの高さの 30% 離れた所から、50% の高さの帯」という同じ意味になります。

この例では近傍背景が正解に一致しましたが、それは合成データの背景が**完全に線形**で、バンドがぼやけていないからです。実際の画像では、どの背景法にも誤差があり得ます。大切なのは、全レーン・全画像で同じ方法を使い、その方法を記録することです。

## (6) 小問

**問 1.** 暗いバンド 2 本（それぞれ 100 画素）の真の S が 2000 と 6000（比 3.0）です。真の背景は 210。背景補正なし（b = 255）で測ると、S と比はどうなりますか。

**問 2.** 上の表で、手動背景 ROI を画像の上端に置いたとき比が 4.23 に**広がった**理由を、(4) の式 S(b) = S(b0) + N × (b − b0) を使って説明しなさい。

**問 3.** 近傍背景で、隣のレーンのバンドが背景帯の中に入ってしまいました。S はどちら向きにずれますか。どう対処しますか。

**問 4.** 先輩が 300 dpi の画像で「近傍背景は間隔 3 px・高さ 5 px」と決めていました。あなたは同じ種類のブロットを 600 dpi で取り込みました（バンド ROI の高さは 24 px）。間隔・高さの比率 30%・50% で設定すると何 px になりますか。また、3 px・5 px をそのまま使うと何が心配ですか。

## (7) 解答・解説

**問 1.**

```
上乗せ分 = N × (255 − 210) = 100 × 45 = 4500
S1 = 2000 + 4500 = 6500
S2 = 6000 + 4500 = 10500
比 = 10500 ÷ 6500 ≈ 1.62
```

真の比 3.0 が 1.62 に縮みます。上乗せ分は弱いバンドにとって相対的に大きいためです。

**問 2.** 上端の b = 172.2 は、バンド位置の真の背景 b0 = 199.8 より 27.6 小さい値です。N = 220 なので、どちらのバンドからも 220 × 27.6 ≈ 6072 が差し引かれます。S1 は 8800 → 2728、S2 は 17600 → 11528 となり、同じ量を引いても弱い S1 の方が相対的に大きく減るため、比が広がります。

**問 3.** 背景帯に暗いバンドの画素が混ざるので b が暗すぎ（暗いバンドでは値が小さすぎ）になり、S は**過小評価**されます。近傍背景の間隔（gap）や高さ（height）を調整する、ROI の位置を見直す、手動背景 ROI に切り替えるなどで対処し、変更した場合はその理由を記録します。全レーンで同じ設定を使うことも忘れないでください。

**問 4.**

```
gap    = round(24 × 0.30) = round(7.2) = 7 px
height = round(24 × 0.50) = 12 px
```

3 px・5 px をそのまま使うと、バンドの高さ 24 px に対して間隔は約 13%・高さは約 21% しかなく、ぼやけたバンドの裾が背景帯に入りやすくなります（b が暗すぎて S が過小評価される）。px の値は解像度とバンドの大きさに依存するので、固定の標準値として受け継がず、相対的な大きさで考えて画像で確認します。30%・50% も目安にすぎません。

**このアプリでの操作：** ［レーン・バンドROI］の「③ 背景」→「h に対する比」に比率を入れて「適用」を押すと、その画像のバンド ROI の高さから間隔・高さ（px）を設定できます。現在の設定が h の何 % にあたるかは［背景補正・定量］画面の上の表に表示されます。［背景補正・定量］画面で背景法を切り替え、表の背景値 b・補正前積分値・S の変化を確認します。学習・ヘルプの「比較・体験」タブでは、同じ画像で背景法を変えたときの S と比の違いを並べて見られます。
